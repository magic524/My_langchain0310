# metrics_v2 指标设计

## 1. 为什么要做 v2

旧版评估存在几个不适合当前阶段的问题：

- 过度依赖“标签和第三方文本相似度”
- 条款级二分类过粗
- `无` 和 `无` 会被算成高分
- 很难解释为什么出现 0% 或 100%

`metrics_v2` 的定位是：

- 接受当前数据并不完美
- 先让结果更符合直觉
- 给后续 agent 接入保留结构化接口

## 2. 当前数据下的 gold label 选择

当前没有人工独立真值，因此只能把“采纳情况说明”视为近似 gold label。

这里明确几个约束：

1. 它不是严格人工标注集。
2. 它可能保留了第三方审查结果的原始表达。
3. 它更接近“业务接受后的风险清单”，而不是“客观穷尽风险全集”。

因此 v2 的结果只用于：

- 比较直觉是否合理
- 发现模型或解析链路的明显问题

不用于：

- 宣称某个系统达到了真实法律审查上限

## 3. 指标设计

在 v2 里，需要明确区分两个概念：

1. 模型输入粒度
2. 评估归因粒度

当前建议是：

- 模型输入粒度
  - 可以是整份合同全文
- 评估归因粒度
  - 仍然落到条款和风险点

原因是：

- 全文输入更符合当前 mentor 的测试要求
- 但如果评估不落到条款和风险点，就无法判断模型到底漏了哪里

### 3.1 两种标签口径

- `adopted_only`
  - 只把 `accept + partial` 当正例
  - 更接近业务实际采纳
- `all_labeled`
  - 采纳情况说明中出现的全部意见都当正例
  - 更接近意见覆盖率

### 3.2 条款层指标

用途：判断模型能否先把值得关注的条款筛出来。

- `Clause Precision`
- `Clause Recall`
- `Clause F1`

计算方法：

- gold 正例：包含至少一个标签风险点的条款
- pred 正例：包含至少一个预测风险点的条款

### 3.3 风险点层指标

用途：判断模型是否把风险点找全、找准。

- `Risk Precision`
- `Risk Recall`
- `Risk F1`

计算方法：

1. 先把风险点对齐到条款
2. 再在同一条款内做一对一匹配
3. 一个标签风险点最多匹配一个预测风险点
4. 一个预测风险点最多匹配一个标签风险点

这意味着：

- 一个条款单元里允许存在多个风险点
- `metrics_v2` 不会因为“同一条款里报出 1 个风险”就默认等价于“该条款全部风险都找到了”

### 3.4 解释结构分

当前不做“语义真伪裁判”，而做更稳妥的结构评分。

每条已匹配风险点从以下维度打分：

- 是否有明确风险标题
- 是否给出风险原因
- 是否说明不利后果
- 是否绑定到对应条款

最终输出平均分。

### 3.5 建议可执行分

每条已匹配风险点从以下维度打分：

- 是否给出修改建议
- 是否包含可执行动作词
- 是否与当前条款绑定
- 是否不是纯占位文本

最终输出平均分。

### 3.6 同源重合提示

为了提醒使用者“当前分数可能被文本同源抬高”，v2 会额外输出：

- `Exact Title Overlap`
- `Exact Suggestion Overlap`

这两个指标不参与总分，只做风险提示。

## 4. 为什么暂时不做更复杂的指标

当前暂不强推以下指标：

- 法律语义正确率
- 风险类型分类准确率
- 修改建议法律安全性自动裁判

原因很简单：

- 样本太少
- 近似 gold label 本身不够独立
- 自动化结论容易看起来精确，实际上不稳

后续如果有更多人工标注数据，再逐步升级即可。
